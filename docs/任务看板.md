# AutoIt v3 内置函数实现任务看板

> **用途**：把 AutoIt v3 官方函数表中尚未落地的内置函数整理成可执行的任务清单，
> 并按「通用」与「需要仿真」分开，供 `autoitv3-runtime` / `autoitv3-platform` 逐项实现。
>
> **依据**：AutoIt v3 官方函数表（`functions.htm`，共 **403** 个内置函数）
> × 本仓库现状（`crates/autoitv3-runtime/src/builtins.rs`、
> `crates/autoitv3-platform/src/{common,linux,windows}/`、`.../winemu/`）
> × 真实脚本对内置函数的使用情况。
>
> **配套文件**：逐函数机器可读状态表见 `docs/函数实现状态.tsv`
> （由源码的 match 分支整理生成）。

## 三、列 A：✅ 已完成 · 通用（67）

全部已落地并有回归测试；逐项状态见 `docs/函数实现状态.tsv`。

| 分组 | 落地位置 | 函数 |
| ---- | ---- | ---- |
| 核心语言（16） | `builtins.rs` / `interp.rs` | `Assign` `Eval` `IsDeclared` `FuncName` `IsBool` `IsFloat` `ChrW` `BitRotate` `MapAppend` `StringIsASCII` `StringIsLower` `StringIsUpper` `StringIsXDigit` `StringStripCR` `StringFromASCIIArray` `StringToASCIIArray` |
| 文件 / 目录（9） | `common/` | `FileChangeDir` `FileGetPos` `FileSetPos` `FileSetEnd` `FileGetEncoding` `FileReadToArray` `FileFindFirstFile` `FileFindNextFile` `FileSetTime` |
| INI（7） | `common/` | `IniRead` `IniWrite` `IniDelete` `IniReadSection` `IniReadSectionNames` `IniRenameSection` `IniWriteSection` |
| 进程 / 执行 / 标准 IO（10） | `common/proc.rs` | `Run` `RunWait` `ProcessWait` `ProcessWaitClose` `ProcessGetStats` `ProcessSetPriority` `StdoutRead` `StderrRead` `StdinWrite` `StdioClose` |
| 网络（25） | `common/net.rs` | `InetGet` `InetGetInfo` `InetGetSize` `InetRead` `InetClose` `FtpSetProxy` `HttpSetProxy` `HttpSetUserAgent` `Ping` `TCPStartup` `TCPShutdown` `TCPConnect` `TCPListen` `TCPAccept` `TCPRecv` `TCPSend` `TCPCloseSocket` `TCPNameToIP` `UDPStartup` `UDPShutdown` `UDPOpen` `UDPBind` `UDPRecv` `UDPSend` `UDPCloseSocket` |

**已记录的近似**（与 README「不静默编造值」一致）：

- `FileGetEncoding` 返回 AutoIt 的 `32/64/128/256/512`，纯 ASCII 返回 `0`
- `FileFindNextFile` 的 `flag = 1`（属性字符串写入 `@extended`）无法表达，退化为 `0`
- `FileSetTime` 的创建时间（`type = 1`）在宿主上不可设置，返回失败
- `StringIsLower`/`Upper` 要求至少含一个字母，且所有字母大小写一致
- `MapAppend` 取"下一个未占用的正整数键"；Map 键在本运行时是字符串，故整数键与
  同数字的字符串键无法区分
- `Run` 的 `show_flag` 在非 Windows 上忽略；`$STDERR_MERGED` 用缓冲区拼接模拟
- `ProcessSetPriority` 只报告成功，不真正改 nice；`ProcessWait`/`WaitClose` 阻塞等待，
  确定性分析配置下立即返回
- `Inet*` 只支持明文 `http://`（无 TLS），`https://` 立即失败；`TCPAccept` 非阻塞
- 网络/进程副作用全部受 `ExecutionProfile` 门控，`deterministic()` 下拒绝执行

## 四、列 B：✅ 已完成 · 需要仿真 · 可落地（28）

全部在 `winemu/` 落地并有回归测试：

| 分组 | 落地位置 | 函数 |
| ---- | ---- | ---- |
| Windows 文件 / PE（7） | `winemu/verinfo.rs`、`winemu/shortcut.rs`、`winemu/mod.rs` | `FileGetVersion` `FileCreateShortcut` `FileGetShortcut` `FileCreateNTFSLink` `FileRecycle` `FileRecycleEmpty` `FileInstall` |
| 回调（4） | `winemu/mod.rs` | `DllCallAddress` `DllCallbackRegister` `DllCallbackGetPtr` `DllCallbackFree` |
| COM（6） | `winemu/mod.rs` | `ObjCreate` `ObjCreateInterface` `ObjEvent` `ObjGet` `ObjName` `IsObj` |
| 系统信息 / 驱动器（6） | `winemu/mod.rs` | `MemGetStats` `IsAdmin` `DriveMapAdd` `DriveMapDel` `DriveMapGet` `DriveSetLabel` |
| 执行 / Shell（5） | `winemu/shell.rs` + `winemu/mod.rs` | `ShellExecute` `ShellExecuteWait` `RunAs` `RunAsWait` `Shutdown` |

**已记录的近似**（与「不静默编造值」一致）：

- `FileGetVersion` 解析 PE 的 `RT_VERSION`（VS_FIXEDFILEINFO + StringFileInfo）；
  没有版本资源时按 AutoIt 语义返回 `"0.0.0.0"` + `@error = 1`
- `FileGetShortcut` 只解析 Shell Link 的 `LinkInfo` + `StringData`；写入不含
  `LinkTargetIDList`，路径按 ANSI 存储
- `FileCreateNTFSLink` 的 junction 用宿主符号链接模拟；宿主不支持时返回失败
- `FileInstall` 先按磁盘文件复制，源不在磁盘时回退到已加载模块的 `RT_RCDATA` 资源
- COM 无运行时：`Obj*` 返回 `0`/`""` 并置 `@error = 1`，`IsObj` 恒为 `0`（不编造对象）
- `DllCallAddress` 无 PE 加载器：地址不可解析，返回 `0` + `@error = 1`
- `DllCallback*` 只分配/登记指针，不会真的被原生代码回调
- `MemGetStats` 返回固定的 8 GiB 仿真机器内存表（可复现）
- `RunAs`/`RunAsWait` 接受凭据但不切换用户；`ShellExecute` 不模拟文件关联
- `Shutdown` 只记录请求并返回成功，绝不真正关机
- 写文件、驱动器映射、启动进程受 `ExecutionProfile` 门控，`deterministic()` 下拒绝

## 五、列 C：✅ 无头 + ✅ 离屏渲染 + ✅ 实时窗口（29 种控件） · GUI / 窗口 / 输入（165）

165 项的**无头语义**全部落地在 `winemu/gui/`：控件是内存对象、句柄是整数，
`GUIGetMsg` 无事件时返回 `0`，`GUICtrlRead` 返回脚本自己设进去的数据，
`GUICtrlSendMsg` 对 `$EM_*`/`$LVM_*` 给出文档化默认值（未知消息置 `@error = 1`）。

分析场景靠脚本化事件收口：`with_gui_events([...])` 预置 `Close`/`Control(id)` 等，
`with_gui_auto_close(n)` 让第 n 次 `GUIGetMsg` 返回 `$GUI_EVENT_CLOSE`，
`with_gui_answers([...])` 给 `InputBox`/`File*Dialog` 提供答案（无答案即按取消处理）。

**渲染（M2c，已完成）**：控件模型与 `GuiBackend` 接缝抽到零依赖 crate `autoitv3-gui`；
`autoitv3-gui-egui`（feature `egui`，默认关）用 egui 布局 + 自带 CPU 光栅器产出 RGBA，
并提供 `snapshot()` / `screenshot()` / `with_screenshot()`。平台侧 `gui-egui` feature
提供 `with_egui_backend()` 与 `gui_snapshot()`。

**完整控件集与交互（M2d，已完成）**：`autoitv3-gui-egui/src/widgets.rs` 是控件 → egui 控件的
唯一映射，离屏与实时窗口共用，29 种 `ControlKind` 全部落地：

| 分组 | 渲染方式 |
| ---- | ---- |
| Label/Button/Input/Edit/Checkbox/Radio/Group | 原生 egui 组件（Button/Input/Edit 用脚本给的 width/height） |
| List/Combo/ListView/TreeView/ListViewItem/TreeViewItem | 可选中的列表/表格（TreeView 用前导缩进表现层级） |
| Progress/Slider/Updown | 读 `text`（值）与 `limit`（范围），拖拽回写 |
| Graphic | 重放 `GUICtrlSetGraphic` 记录下的 `DrawCmd`（线/矩形/椭圆/文字/颜色/线宽） |
| Pic/Icon/Avi/Obj/Date/MonthCal/Tab/TabItem | 占位框或文本（模型里没有真实位图/媒体） |
| Menu/MenuItem/ContextMenu | 窗口顶部菜单栏 |
| Dummy | 不画（AutoIt 里也没有外观） |

绘制同时返回 `Interaction`（`Clicked`/`Menu`/`Text`/`Checked`/`Selected`）：`EguiBackend`
丢弃它，`LiveBackend` 把它变成 `GuiEvent::{Control,Menu}` 或
`GuiUpdate::{SetText,SetChecked,Select}`。控件的字体/文字色/背景色/`tip` 一并生效。

实现细节：`egui 0.36` 的 `begin_pass`/`end_pass` 在首帧只给 Noop shapes，离屏必须用
`Context::run_ui`；`TexturesDelta` 不 apply 就必须 `clear()`，否则 drop 时 panic。

中日韩文字：egui 自带字体无 CJK，控件里的中文会画成方块——`fonts.rs` 从系统字体里找
（`AU3_GUI_FONT`/`AU3_GUI_FONT_INDEX` 可指定；否则按候选路径与目录浅扫），以
`FontPriority::Lowest` 作为回退装入（拉丁仍用 egui 字体）。实时窗口在 eframe 的
`AppCreator` 里装、离屏渲染器在 `EguiBackend::new()` 里装；找不到会打印提示。
`tests/fonts.rs` 用 `Fonts::has_glyphs` 与"两段不同中文必须渲染出不同像素"守这条
（去掉回退字体会报 `different Chinese text rendered identically`）。

字体图集：egui 首帧发整张、之后用**局部补丁**（`ImageDelta.pos`）加新字形。离屏缓存要按
矩形把补丁贴回去（`raster::apply_textures`，已公开导出，与 `rasterize`/`Texture` 配套），
否则"后出现的字形"（新字符、另一种字号）会画不出来——`raster.rs` 的单测
`a_patch_updates_only_its_rectangle` 守这条。

**线程模型**：winit 不允许在主线程之外建事件循环（否则 panic），所以
`LiveBackend::run(script)` **在主线程**跑 eframe、把脚本放到工作线程；脚本返回时置
`finished`，窗口据此自行关闭，`run()` 于是会返回，不会留下空窗口。`LiveBackend` 可
`Clone`，克隆共享同一个窗口。

**窗口尺寸与状态（双向）**：

- 模拟窗口 = `GUICreate` 的客户区大小（首帧按它铺开，四个边/角都能拖，横竖皆可）；
- **用户 → 脚本**：拖动的新尺寸经 `GuiUpdate::Resize` 回写模型，`WinGetPos`/
  `WinGetClientSize` 与 `$GUI_EVENT_RESIZED`(-12) 都跟着变；
- **脚本 → 屏幕**：`WinMove`/`WinSetState` 改模型后窗口立刻跟随（`show_autoit_window`
  在几何变化的那一帧用 `current_pos` 定位——egui 的 `Window` 默认 `TitleBar` 拖拽模式
  每帧会用**存档位置**覆盖 `current_pos`，所以那一帧要切成 `Anywhere`）；
- 最小化/最大化：最大化铺满视口；最小化按 `MinimizeStyle` 呈现——
  `Hidden`（默认，仿真：离开屏幕 + 实时窗口底部一条可点恢复的"任务栏"）或
  `TitleBar`（保留标题栏、藏内容，双击标题栏恢复）。两个后端（离屏/实时）都用同一套规则；
- 标题栏右侧有**最小化 / 最大化（还原）按钮**：`ui.interact` + 自绘，不进布局流（否则会改变
  egui 对内容尺寸的测量），画在窗口自己的图层里（因此在标题栏拖拽控件之上）；样式照抄 egui 的
  关闭按钮（`spacing.icon_width` 方形 + `item_spacing.x` 间距 + `fg_stroke` 线条、无底色、
  悬停按 `visuals.expansion` 放大），并由像素级测试守住"是线条不是色块"；
- 标题栏**双击 = 最大化/还原**（关掉 egui 默认的"双击折叠"）；点在按钮上不算双击；
- **模拟桌面**：`GuiBackend::desktop_size()`（实时=原生视口、离屏=画布、无头=1024×768），
  `@DesktopWidth/@DesktopHeight` 读它（此前这两个宏**没有实现**，返回空串）；
- 最大化会把窗口矩形换成桌面矩形（`WinGetPos` 随之返回桌面尺寸），原矩形存进
  `Window::restore` 供 `@SW_RESTORE` 还原；桌面变化时已最大化的窗口跟着变并收到
  `$GUI_EVENT_RESIZED`；实时窗口向原生视口请求 1024×768 作为初始尺寸，避免首帧前后不一致；
- **踩过的坑（记账）**：窗口的"外框余量"（outer − 画出的 client）必须由**当帧真正画出的尺寸**
  算出，并随 `LastWindow` 传给下一帧；调用方若用"自己记的客户区尺寸"去量，就会在最大化/最小化
  那一帧量出巨大的余量，下一帧把 `desired_size` 算回旧值——窗口于是逐帧在"最大化 ↔ 还原"之间
  抖动，`Window::max_size` 的夹紧也失效（还原不回宽度、位置被贴边约束改写成 0,0）。现在这段
  记账集中在 `widgets::record_drawn`，实时后端与测试走同一条路径，
  `a_maximised_window_does_not_oscillate` / `restoring_a_maximised_window_brings_back_both_axes` 守它；
- **还原时宽度也回来**：egui 的窗口尺寸跟着它自己保存的 `desired_size` 走（内容里的 ScrollArea
  会把它填满），只有 `Window::max_size` 能压小它——按"目标尺寸 + 实测外框余量"夹住，
  指针按下时放开让拖拽说话；
- 用户在窗口上的状态操作（双击标题栏、点任务栏恢复）经 `GuiUpdate::SetWindowState`
  回写模型，脚本收到 `$GUI_EVENT_MINIMIZE`(-4)/`RESTORE`(-5)/`MAXIMIZE`(-6)。

`WinMove` 之前把 `text` 参数当成了 `x`（真实签名是 `WinMove("title","text",x,y[,w[,h]])`），
现在按 AutoIt 解析，缺失/`-1` 的参数表示"那一维不动"。`@SW_*` 宏（0…11）已补齐，
`WinSetState` 改用 `@SW_*` 语义（`@SW_MINIMIZE`=6，与 `WinGetState` 的位标志不同）。

测试：`tests/window_resize.rs`（模拟指针拖拽 + 脚本侧 WinMove + 最小化/最大化）、
`tests/controls.rs`（离屏的状态语义）、`tests/winemu.rs`（`WinMove`/`WinSetState`/`@SW_*`
到达模型与 backend）。

**仍未接线**：`Win*`/`Control*` 只改内存模型、不真的搬动窗口；托盘、
`PixelGetColor`/输入注入没有真实数据源；菜单→菜单项的父子关系模型里没有保留，
所以每个菜单列出本窗口所有菜单项；控件按创建顺序纵向排列，不按绝对 `x`/`y`。

**测试**：`tests/controls.rs` 逐种控件渲染（与空窗基线做像素差）+ 整窗画廊 + 确定性；
`widgets.rs` 内的单测用模拟指针事件验证点击/输入/勾选/列表选择；
`crates/autoitv3-platform/tests/gui_egui.rs` 跑完整脚本，断言 29 个控件都到达渲染器并出像素。

## 八、验收标准

1. **语义可判定**：新增函数要么给出真实结果，要么按 AutoIt 语义失败并置 `@error`；
   不允许"静默编造值"（与 README「不静默编造值」一致）。
2. **受执行配置约束**：写文件/注册表/网络/启动进程等副作用必须走
   `ExecutionProfile`，`deterministic()` 下拒绝。
3. **归层正确**：平台无关与宿主进程/网络进 `builtins.rs`/`common/`
   （`proc.rs`/`net.rs`），Windows 语义进 `winemu/`；
   `Platform` trait 之外不新增平台耦合。
4. **有回归测试**：每个函数一个用例，覆盖正常路径、边界（空值/不存在/权限）与 `@error` 行为。
5. **可复现**：涉及随机/时间的函数在 `deterministic()` 下结果稳定。
